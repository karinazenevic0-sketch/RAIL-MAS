# МАС: железнодорожные перевозки грузов (JADE) — каркас

Каркас по схемам `1_etap1_dopustimyi_plan`, `2_etap2_rebalansirovka`, `3_otkaz_vagona`.
Нужны JDK 21+, `lib/jade.jar`, `lib/gson-2.13.1.jar`.

## Агенты
| Агент | Где | Роль |
|---|---|---|
| `CoordinatorAgent` | сервер | только ПОЛУЧАЕТ отчёты, проверяет допустимость, считает критерии, пишет `out/*.json`, `out/report.html` |
| `StationAgent` | сервер | окна погрузки/приёма (число путей), перенос и обмен окон |
| `LocomotiveAgent` | сервер | брони по интервалам, ограничение суммарной тяги, атомарный обмен броней |
| `WagonAgent` | клиент | **считает стоимость** (тариф + 0,75·порожний км + 25·часы опоздания), совместимость, очистка, временная блокировка интервала, бронь, обмен рейсов, отказ |
| `CargoAgent` | клиент | **сам знает** тип, вес, дедлайн; ищет вагон; на этапе 2 сам опрашивает ВСЕ грузы; при отказе сам ищет замену |

## Запуск
* Один компьютер: `run\local.bat` (`railway.LocalMain`).
* Два компьютера: ПК1 — `railway.ServerMain` + `ClientMain <IP ПК1> cargo pc1`;
  ПК2 — `ClientMain <IP ПК1> wagons pc2 <свой IP>`. Порядок любой: грузы стартуют, когда в DF видны все агенты.
* На обоих компьютерах одна версия кода и `data/input.json`.

## Незапланированные ситуации
* В `input.json`, секция `failures` (отказ вагона через `atMs` мс после старта).
* Вручную в консоли клиента «вагоны»: `fail wagon_h1 20:00`.

## Результат
`out/initial_plan.json`, `out/improved_plan.json`, `out/recovery_plan.json`, `out/report.html`.
